大六壬九宗门，怎样取出三传？

起课入口负责确定最终占时，九宗门负责在四课生成后判断初传。把这两层分开，才能复核一课为什么得到初传、中传和末传。

完整链路

正时、报数或指定时支 → 日干支与月将 → 天地盘 → 十二天将 → 四课 → 九宗门条件判定 → 初传、中传、末传 → 旬空、遁干、六亲与课体。每一步都应保存输入和规则版本。

用固定输入做实例

例如固定一个公历日期、Asia/Shanghai 时区和实际时刻，指定“正时起课”。程序先把日期转换为日干支并确定月将，再把最终占时支放入天地盘。若改成报数起课，报数只改变最终占时支，日期、日干支和月将仍按同一组基础资料计算。

四课之后才看九宗门

四课描述日干、日支及其所临的上下神。程序先检查是否满足贼克、比用、涉害、遥克等条件，再按实际命中的规则取初传；如果进入昴星、别责、八专、伏吟或返吟，也应把命中原因写入结果。用户不应在九个按钮里随意挑一个“看起来合适”的门。

三传如何保持可复核？

  1. 记录初传来源：哪一课、哪一神、哪条九宗门条件命中。
  2. 按传局规则从初传推中传，再推末传。
  3. 同时输出三传遁干、旬空、六亲和课体标签。
  4. 如果另一引擎结果不同，保留重叠字段和差异，不静默覆盖。

为什么要做多引擎校验？

大六壬实现可能在贵人法、昼夜界定、月将边界和课体细节上采用不同口径。命序保留自己的可审计结构层，并用固定版本的第二 TypeScript 引擎和 Python 课例比较重叠字段。交给 AI 时，应把 warning/crossCheck 一并提供。

结果不是自动的吉凶结论

四课三传属于程序整理的结构事实；传统规则的含义和具体问题的解释仍需明确语境。先把问题、占时和计算事实分开，再让 AI 或专业人士讨论，不要把一张课盘包装成确定的现实预测。
