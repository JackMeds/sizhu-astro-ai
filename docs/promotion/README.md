## Developer-community angle

Title idea:

> Why I stopped asking LLMs to calculate BaZi and gave them deterministic MCP tools instead

Core story:

1. LLMs are useful at explanation but unreliable at repeatedly calculating calendars and rule-heavy chart structures.
2. MingXu moves deterministic computation into code.
3. The browser and Agent share one visible WebMCP workspace.
4. The same computation layer is exposed through MCP for other clients.
5. Boundary cases and cross-engine differences are public instead of hidden.

## Directory submission checklist

Before submitting:

- public endpoint returns healthy response;
- README contains current install/connect instructions;
- `/agent/` and `agents.md` agree with actual tool names;
- benchmark link works;
- source repository is public;
- license is visible;
- no secrets or personal test data are exposed.

Suggested order:

1. Official MCP Registry
2. Glama
3. Smithery
4. WebMCP.com
5. WebMCP Directory
6. MCP.so / MCPServers.org
7. relevant Awesome MCP / WebMCP lists

## Community rules

- Teach first, link second.
- Never buy or mass-generate backlinks.
- Never attack paid competitors; state what MingXu does differently.
- Do not ask for stars as the primary CTA.
- Prefer requests for reproducible edge cases, code review, translation and test contributions.
- If a community prohibits self-promotion, do not post there merely for a backlink.

## Product claims we can safely make

- free core web calculator;
- open-source GPL-3.0 code;
- no account required for core web calculation;
- local-first browser workflow;
- deterministic calculation layer;
- public boundary/cross-check tests;
- WebMCP and MCP integration.

Do not claim scientific predictive validity, guaranteed accuracy across every traditional school, or privacy guarantees for data the user explicitly sends to a third-party AI.
